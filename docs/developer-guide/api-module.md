# The Argo CD API Go module

The Argo CD CRD types (`Application`, `AppProject`, `ApplicationSet`) and the generated clientset
live in a separate Go module:

```text
github.com/argoproj/argo-cd/api/v3
```

It is a nested module in this repository, at `./api`, wired into the root module with a `replace`
directive in the same way as `./gitops-engine`.

## Why it exists

Projects that integrate with Argo CD — operators, controllers, CLI tools — usually need only the
CRD types and the clientset. Before the split they had to depend on the whole of
`github.com/argoproj/argo-cd/v3`, which transitively pulls in `k8s.io/kubernetes`.

Because the Kubernetes staging repositories (`k8s.io/kubelet`, `k8s.io/component-helpers` and the
rest) are published only as `v0.0.0` placeholder versions, anything reaching `k8s.io/kubernetes`
forces every consumer to copy Argo CD's full set of `k8s.io/*` `replace` directives into their own
`go.mod` just to make `go mod tidy` succeed — and that pins their Kubernetes library versions to
Argo CD's.

The API module removes that entirely.

| | Root module | API module |
| --- | --- | --- |
| `k8s.io/*` replace directives the consumer must copy | ~35 | 0 |
| Modules in the build list | 455 | 195 |
| Non-stdlib packages compiled | 1084 | 343 |

## Using it

```go
import (
	"github.com/argoproj/argo-cd/api/v3/pkg/apis/application/v1alpha1"
	"github.com/argoproj/argo-cd/api/v3/pkg/client/clientset/versioned"
)
```

```text
require github.com/argoproj/argo-cd/api/v3 v3.x.y
```

No `replace` directives are required.

## Migrating from the old import paths

The old paths under `github.com/argoproj/argo-cd/v3` still work for one release cycle, via
generated shims that re-export the moved packages. Migration is a find-and-replace:

```bash
grep -rl 'github.com/argoproj/argo-cd/v3/pkg/apis' --include='*.go' . \
  | xargs sed -i 's#github.com/argoproj/argo-cd/v3/pkg/apis#github.com/argoproj/argo-cd/api/v3/pkg/apis#g'
grep -rl 'github.com/argoproj/argo-cd/v3/pkg/client' --include='*.go' . \
  | xargs sed -i 's#github.com/argoproj/argo-cd/v3/pkg/client#github.com/argoproj/argo-cd/api/v3/pkg/client#g'
```

Then require `github.com/argoproj/argo-cd/api/v3` instead of the root module and delete the copied
`k8s.io/*` `replace` block.

> [!IMPORTANT]
> The shims keep the old paths *compiling*, but they live in the root module. A consumer importing
> them still depends on `github.com/argoproj/argo-cd/v3` and therefore still needs the `k8s.io/*`
> replace directives. The dependency reduction only arrives once you import the API module
> directly.

The following packages also moved into the API module, because the types depend on them:
`util/env`, `util/glob`, `util/hash`, `util/regex`, `util/security`, `util/git/giturl`,
`util/helm/helmurl`, `util/kubetransport` and `util/rbac/actions`. Each has a shim at its old path
as well.

### Changes the shims cannot cover

Type aliases preserve methods and type identity — an `*Application` obtained through a shim is the
same Go type as one from the API module, and the two can be passed between each other freely. Two
changes are not expressible as aliases:

**Credential constructors moved off `Repository`.** Go does not permit declaring methods on a
non-local type, so these could not be re-attached:

```go
// before
creds := repo.GetGitCreds(store)
creds := repo.GetHelmCreds()
creds := repo.GetOCICreds()

// after
import "github.com/argoproj/argo-cd/v3/util/repocreds"

creds := repocreds.GetGitCreds(repo, store)
creds := repocreds.GetHelmCreds(repo)
creds := repocreds.GetOCICreds(repo)
```

They now live in the root module, since constructing credentials needs `util/git`, `util/helm`,
`util/oci`, `util/cert` and `util/workloadidentity` — go-git, oras-go and the Azure SDK between
them. Keeping that out of the API types is what makes the module light.

**The health and sync enums are now declared by the API module.** `HealthStatusCode`,
`OperationPhase`, `ResultCode`, `SyncPhase` and `HookType` were previously gitops-engine types. The
values are identical, but they are distinct Go types, so code that passes them into gitops-engine
needs an explicit conversion:

```go
// before
engineStatus := app.Status.Health.Status

// after
engineStatus := health.HealthStatusCode(app.Status.Health.Status)
```

Code that only creates and reads Argo CD resources is unaffected. Both changes are compile-time
errors, so the compiler finds every site.

## Working on the API module

The generated code is produced by the usual target, which regenerates both modules:

```bash
make codegen
```

The generators run with the API module as the main module, because they derive the generated
import paths from it.

The shims are generated by `hack/gen-api-aliases`, which runs as part of `make codegen`. They are
marked `DO NOT EDIT`; to change what is re-exported, change the API module and regenerate:

```bash
make api-aliases
```

Unit tests for the module run under their own target, as gitops-engine's do:

```bash
make test-api
```

> [!NOTE]
> The API module pins its Kubernetes dependency versions with `require`, not `replace`. A `replace`
> directive in a dependency is ignored by the module that consumes it, so pinning that way would
> leave consumers resolving incompatible versions of `k8s.io/apimachinery` and
> `sigs.k8s.io/structured-merge-diff`. `sigs.k8s.io/kustomize/api` is held at a version compatible
> with the pinned `k8s.io/kube-openapi` for the same reason. Take care not to let `go mod tidy`
> float these.
